4. Technical Analysis: Merging Weekend 1 Check-Ins via IP Address

The client inquired:

"Is there a way to merge check-ins from the first weekend by the user’s IP address? If so, can we compile a list of all users with 8+ check-ins."

Key Findings:

No IP Addresses Stored in the Database:

The database intentionally never stored IP addresses in table schemas to maintain privacy, avoid collecting sensitive tracking data, and keep the database clean.

Server Access Log Retention Window:

The Linux web server uses standard daily log rotation with 7-day retention (rotate 7). The logs currently on disk begin on November 10. Server access logs for November 6–8 have already been rotated out by the operating system.

Mobile Cellular IP Characteristics (CGNAT):

Even if raw web logs existed, mobile phones on cellular networks (Verizon, AT&T, T-Mobile) do not have static IP addresses. As tour visitors drive from home to home across Marion County, their phones switch cell towers and obtain different dynamic IP addresses. Additionally, hundreds of mobile devices share the same carrier gateway IP (Carrier-Grade NAT). Thus, IP addresses cannot reliably bind an anonymous mobile check-in to a specific registered individual.

The Automatic Browser Sync Already Worked:

The app stored visited homes in the device's local storage (localStorage). When visitors who toured in Weekend 1 logged into or opened their pass on that same phone, the app automatically synced those check-ins to their account!

This is why Weekend 1 participants like Christina Peters (clpwgp@gmail.com, registered Nov 7) and Devindra Singh (devindrasingh85@gmail.com, registered Nov 8) successfully have their 9 check-ins credited and appear on the 8+ qualifier list.
